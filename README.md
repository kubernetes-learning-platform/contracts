# contracts

> **The Protobuf schema for the whole system**, published as a NuGet package for .NET and an npm package for TypeScript.

Part of [**kubernetes-learning-platform**](https://github.com/kubernetes-learning-platform/docs), an AI tutor with a live Kubernetes lab. Start at the [docs hub](https://github.com/kubernetes-learning-platform/docs) for the big picture.

**Owner:** Filip · **Status:** planned layout. A `v0.1` with stub messages ships early in M1 so `api` and `web` can build against real types.

---

## 🧩 Why one schema

Every message that crosses a process boundary is defined here, once:

| Boundary | Transport | Messages |
|---|---|---|
| browser ↔ `api` | WebSocket, binary frames | `ClientMessage` / `ServerMessage` |
| browser → `api` | REST | request/response bodies |
| `api` ↔ `envmgr` | gRPC over the WireGuard mesh (Hetzner box → Proxmox box) | `EnvironmentManager` service |
| `api` ↔ `envmgr` | RabbitMQ over the WireGuard mesh (sandbox start and teardown only) | `ProvisionRequest`, `ProvisionResult`, `TeardownRequest` |
| `envmgr` ↔ `harness` | WebSocket, one binary message per frame (every provider) | `HarnessFrame` |

A field change is one PR here, then a version bump in each consumer.

## 📄 Proto files

All under `proto/kubernetes_learning/v1/`:

| File | Defines |
|---|---|
| `common.proto` | IDs, timestamps, errors |
| `envmgr.proto` | The `EnvironmentManager` gRPC service, `Sandbox`, `SandboxStatus` |
| `harness.proto` | `HarnessFrame` plus the hello (sandbox id + one-time token), exec, PTY, file, fault, check and snapshot-request messages |
| `topology.proto` | `Entity`, `Edge`, `TopologySnapshot`, `TopologyDiff`, `ClusterEvent`, `TrafficSample` |
| `view.proto` | `ViewIntent`: focus, highlight, annotate, show_config, clear |
| `session.proto` | `ClientMessage` / `ServerMessage` for the browser socket, including helper questions (`AgentQuestion`, `AgentAnswer`), `HelperState` and `ScenarioProgress` |
| `rest.proto` | REST request and response bodies |
| `jobs.proto` | `ProvisionRequest`, `ProvisionResult`, `TeardownRequest` for the RabbitMQ work queue |

## 📦 Packages

| Package | Registry | Contents | Used by |
|---|---|---|---|
| `KubernetesLearning.Contracts` | GitHub Packages (NuGet) | Messages + gRPC client and server stubs, compiled by `Grpc.Tools` | `sandbox`, `api` |
| `@kubernetes-learning-platform/contracts` | GitHub Packages (npm) | Messages generated by protobuf-es | `web` |

The harness only uses the messages. Native AOT trimming drops the gRPC stubs.

## 🏷️ Versioning

- A `vX.Y.Z` tag publishes a release.
- Every merge to `main` publishes a prerelease, `X.Y.Z-main.<run>`, so consumers can try unreleased changes.
- `buf lint` and `buf breaking` (against `main`) gate every PR.
- While on `0.x`, breaking changes are allowed but must bump the minor version.
- The placeholder name has to be replaced **before 1.0**. After that, renaming the proto package is a breaking wire change. See [ARCHITECTURE §12](https://github.com/kubernetes-learning-platform/docs/blob/main/ARCHITECTURE.md#12-naming).

## 📁 Layout

```
contracts/
├── proto/kubernetes_learning/v1/      # the .proto files above
├── buf.yaml                           # lint + breaking rules
├── buf.gen.yaml                       # protobuf-es codegen
├── dotnet/KubernetesLearning.Contracts/
│   └── KubernetesLearning.Contracts.csproj   # Grpc.Tools compiles ../../proto at build time
├── ts/
│   ├── package.json                   # @kubernetes-learning-platform/contracts
│   └── src/gen/                       # generated, not committed
└── .github/workflows/ci.yml           # calls platform's proto-ci.yml
```

## 🔑 Installing the packages

GitHub Packages needs a token even to read. Create a classic personal access token with `read:packages` once, and use it for both registries.

**.NET**

```bash
dotnet nuget add source https://nuget.pkg.github.com/kubernetes-learning-platform/index.json \
  --name kubernetes-learning-platform \
  --username YOUR_GITHUB_USERNAME \
  --password YOUR_TOKEN \
  --store-password-in-clear-text
```

**npm** (`.npmrc` in the consuming repo, with the token in an env var):

```ini
@kubernetes-learning-platform:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_PACKAGES_TOKEN}
```
